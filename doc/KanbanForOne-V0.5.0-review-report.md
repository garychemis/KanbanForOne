# KanbanForOne V0.5.0 发布前 Review 报告

- 审查日期：2026-08-19
- 审查范围：V0.5.0 全部工作区改动、设计条件归档、统一备份恢复、数据库迁移、附件安全、WPF 运行路径、依赖与 win-x64 发布产物
- 最终结论：**可以发布（Ship）**

## 1. 结论

本轮从数据安全、恢复原子性、输入文件安全、运行时稳定性、依赖供应链和真实发布产物六个方向重新审查。新增发现 7 类问题，其中包含 1 个数据恢复 Critical 和 2 个安全 High/Major；已全部修复并回归。

截至最终复审：

- 无未修复的 Critical、High 或 Major 发布阻断项。
- Release 构建 0 警告、0 错误。
- 77/77 自动化测试通过，包含 WPF UI 冒烟及统一备份双数据库、双附件目录端到端恢复。
- 应用与测试项目的已知漏洞包均为 0。
- 应用运行时无弃用包；测试项目仅保留 xUnit v3 当前稳定版内部的 3 个兼容性传递包，不进入发布产物。
- win-x64 自包含目录式发布成功，EXE 与运行时依赖一并输出，并通过 5 秒进程启动冒烟。

## 2. 本轮发现并修复的问题

### R1 · Critical：核心数据恢复失败时可能删除尚未归位的旧数据

旧 `BackupService` 只用一个布尔值表示数据库、附件和人工时配置的整体移动状态。移动阶段部分成功后抛错，或回滚自身抛错时，外层 `finally` 仍会删除 `.restore-staging`，存在把唯一旧副本随现场一起删除的风险。

修复：分别跟踪数据库、附件目录和人工时选项的移动状态；回滚逐项处理并收集异常；回滚不完整时抛出聚合异常并保留恢复现场；仅在恢复成功或完整回滚后清理 staging。

### R2 · High：SQLite 原生运行时存在已知高危漏洞

NuGet 审计发现 `SQLitePCLRaw.lib.e_sqlite3 2.1.10` 命中 `GHSA-2m69-gcr7-jv3q`。

修复：`Microsoft.Data.Sqlite` 升至 `10.0.11`，显式使用 `SQLitePCLRaw.bundle_e_sqlite3 3.0.5`；最终漏洞审计对应用和测试项目均返回 0。

### R3 · Major：统一备份中的核心子包缺少解压资源限制

统一备份外层包已有固定结构校验，但嵌套 `core.zip` 原先没有条目数、单项大小、总展开量、重复路径、未知路径和磁盘空间限制。

修复：

- 核心包最多 20,000 个条目、单条目 2GB、总展开量 10GB。
- 人工时配置和各级 manifest 单独限制为 1MB，避免 metadata 内存放大。
- 拒绝重复路径、绝对路径、`.` / `..` 路径段及未知文件。
- 核心数据库增加 `PRAGMA quick_check`、schema version、全部必需表与列检查。
- 恢复前按展开和二次复制需求检查可用磁盘空间。
- 同步强化设计条件包和完整外层包的绝对路径及 metadata 大小检查。

### R4 · Major：完整恢复回滚失败时会清理诊断现场和临时保护包

统一恢复原先在 `finally` 中无条件删除模块级临时保护包与完整恢复目录。若整体回滚未完成，这些文件恰恰是人工恢复材料。

修复：完整成功或完整回滚后才删除临时保护包；回滚不完整时保留完整恢复目录及模块临时保护路径；附件数改用两个模块的实际恢复结果，不信任外部 manifest 的声明计数。

### R5 · Major：危险附件可直接 Shell 执行，弹窗未捕获打开异常

主附件和设计条件附件通过 `UseShellExecute=true` 打开，脚本、可执行文件和系统快捷方式可被直接运行；设计条件弹窗事件也未捕获文件异常。

修复：新增统一 `AttachmentOpenSafety`，阻止可执行文件、脚本、安装包、控制面板项、注册表文件和系统快捷方式直接打开；普通 DWG、PDF、XLSX 保持可用；设计条件弹窗在验证提示区显示打开/定位错误。

### R6 · 已按交付选择调整发布模式

最终选择恢复为自包含目录式发布：`KanbanForOne.exe` 与所需托管/原生依赖一起输出，目标电脑无需预装 .NET。继续关闭 PDB 输出，避免发布不必要的调试信息。发布时必须整体分发该目录，不能只复制 EXE。

### R7 · Minor：测试工具链老化及测试数据残留

修复：测试框架迁移至 `xunit.v3 3.2.2`，Test SDK 升至 `18.9.0`，覆盖率收集器升至 `10.0.1`；修复新分析器提示；UI 冒烟在 `finally` 中关闭应用、清理连接池和测试数据；新增完整备份创建、删除双模块记录与附件、整体恢复验证。

## 5. 非阻断剩余风险

1. 磁盘满、杀毒软件拦截、权限变化等故障无法在普通 CI 中穷举；当前通过分项回滚、保护备份和现场保留降低风险。正式发布前仍建议在非开发机上手工做一次“大附件 + 恢复中断”演练。
2. xUnit v3 当前稳定包内部仍依赖 3 个 NuGet 标记为 Legacy/Other 的测试期兼容包；它们无已知漏洞、不进入应用发布包，不构成发布阻断。
3. 当前采用目录式发布，交付或升级时必须整体复制发布目录；遗漏或混用 DLL 会导致启动或版本加载失败。

## 6. 发布判定

**Ship。** 当前代码、测试、依赖和实际发布产物达到 V0.5.0 发布条件。发布时应使用 `FolderProfile.pubxml` 生成 win-x64 自包含目录，并整体分发该目录；不应只复制 EXE，也不应直接分发普通 `bin/Release/net8.0-windows` 构建目录。
