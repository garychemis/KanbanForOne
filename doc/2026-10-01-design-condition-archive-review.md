日期：2026-10-01

## 结论

按业务、数据库及备份、前端三个方向交叉复核，并用实际 WPF 渲染检查界面。发现的问题已修复；最终全量 Debug 测试 142 项通过，无失败、无跳过，Release 构建 0 警告、0 错误。在本次检查范围内，没有已知未解决的问题。

页面采用两个 Tab：「提出设计条件归档」使用青绿色，「接受设计条件存档」使用靛紫色。两类记录保留独立筛选和列表/汇总显示状态，新增、编辑、日历、导出及备份流程均已接入。

## Review 发现与修复

| 问题 | 修复 | 验证 |
| --- | --- | --- |
| 升级前备份可能把 V3 数据库标为 V4；备份期间迁移也可能使清单版本和库内容不一致 | 使用 SQLite 备份 API 生成独立快照，从同一快照读取版本、校验并归档；临时快照放在备份目录并在结束后清理 | V3 升级前备份、备份与迁移并发、恢复往返、未初始化数据库拒绝备份 |
| 数据重置或加载失败后，旧缓存可能继续出现在列表或导出中 | 清除缓存及统计，仅在加载完成且无错误、有记录时允许导出 | 重置、加载中、加载失败与恢复成功后的状态及命令检查 |
| 双击表头或空白区域可能打开此前选中的记录 | 仅左键双击实际数据行时打开该行记录 | 列表和汇总均验证表头、空白、右键、行双击及 Enter |
| 保存校验提示位于可滚动区域，附件较多时不易看到 | 提示移入固定底部操作区，支持换行和辅助技术通知 | 实际点击无效表单的保存按钮，验证提示可见、在窗口内且不属于滚动区域 |
| 1100 像素宽窗口的日期框截断已填写日期，长文本列间距偏挤 | 为日期筛选和日期列保留最小宽度，单元格模板明确应用内边距 | 检查实际日期文字宽度、长文本列表和汇总截图 |
| 筛选后无结果仍显示首次使用提示 | 根据筛选状态显示“没有匹配的条件”，提供“清除筛选”操作 | ViewModel 属性通知、Tab 状态隔离及真实按钮点击 |

## UI 调整

以现有人工时汇总页为参照，继续使用项目的圆角面板、柔和背景、字体层级和控件结构。

- 页面标题跟随当前归档类别主题；Tab 数量采用浅底圆角徽标。
- 长项目号、条件名称、专业和附件文件名采用省略显示，并保留完整内容提示。
- 汇总空状态移除多余嵌套卡片，与列表保持一致。
- 补充 Tab、模式切换和下拉选项的键盘焦点状态。
- 提出及接受主题均支持亮暗实时切换；颜色之外保留明确类别文字。

## 数据与兼容边界

数据库 V4 通过新增类别及接受日期字段扩展原有表。旧记录默认归入提出条件，保留 ID、多图幅信息和附件关联。接受条件的筛选、日历及排序使用接受日期，并保留提出日期。

新版支持迁移 V1–V3 数据库并恢复旧备份；提出条件的 Excel 工作表名称和原有 14 列保持兼容。旧程序不能读取 V4 数据库；需要回退时，应使用旧程序和升级前完整备份。

测试使用隔离数据目录。本次未对用户正式数据执行迁移，也未进行发布。
