# 设计条件双向归档实施规划

日期：2026-10-01

## 已确定的范围

团队先分别审查现有业务、数据库及前端，随后按本方案实施。用户已确认采用同一页面内两个 Tab 切换。

- 默认 Tab 为「提出设计条件归档」，承接全部旧记录。
- 新增「接受设计条件存档」，独立显示记录、筛选、统计和导出结果。
- 复用现有多图幅、附件事务、整体备份和恢复流程。
- 接受条件保留提出日期，另填接受日期；新建时两者默认当天，均可修改。

## 前端与交互

同一导航入口内依次排列页面标题与操作、两个 Tab、列表/汇总切换及统计、筛选和数据表。Tab 显示分类名称和该类总记录数，统计卡显示当前筛选结果。切换 Tab 保留各自筛选与显示模式。

提出使用现有青绿色，接受使用靛紫色。亮色与暗色分别配置语义画刷，页面、表格选中/悬停、主按钮及编辑器跟随分类。Tab 和日历记录同时显示分类文字，避免只靠颜色识别。

新建由当前 Tab 确定类别，编辑时保持原类别。日历提供提出和接受两个新增入口。列表支持双击及 Enter 打开。

## 数据库 V4

继续使用独立 `DesignConditions.db` 和原三张表；主数据库保持现有结构。

| 字段 | 存储 | 规则 |
| --- | --- | --- |
| `ArchiveKind` | INTEGER NOT NULL DEFAULT 0 | 0 = 提出，1 = 接受，限制为这两个值 |
| `IssuedDate` | 保留原 TEXT 字段 | 记录实际提出日期 |
| `ReceivedDate` | 新增可空 TEXT | 接受记录必须填写，日期按 yyyy-MM-dd 存储 |
| `ArchiveDate` | 应用层计算属性 | 提出取 IssuedDate，接受取 ReceivedDate |

迁移在事务内完成，新字段默认使旧记录归为提出，保留所有原 ID、业务字段、多图幅数据和附件路径。增加按类别与业务日期查询的索引。初始化必须幂等。

页面日期筛选、排序、日历当天/日期范围及统计使用 ArchiveDate。既有仓储日期方法签名继续可用，其查询口径扩展为相应类别的业务日期。

## 导出及备份

- 提出 Excel 保留既有工作表名称和列序，以及折 A1 计算方式。
- 接受 Excel 使用明确的接受条件工作表名称，按接收专业汇总；明细显示接受日期并保留提出日期。
- 导出只允许当前类别，避免跨类别合计。
- 备份包格式继续为 1，数据库升级为 4；清单记录包内数据库快照的实际版本。恢复仍接受 V1–V3 数据库并自动迁移。
- V4 备份校验新增字段与数据约束，独立备份和整体备份均包含两类记录及附件。

## 兼容边界与回退

兼容范围为新版读取既有数据库和恢复既有备份，不要求手工重新录入、重新关联附件。升级保持现有 V1/V2 多图幅迁移规则。

已发布的旧程序会拒绝高于自身支持版本的数据库，因此 V4 库不能直接交给旧程序使用。正式升级前应先用旧程序创建完整备份；需要回退时使用旧程序及升级前备份。新版创建的 V4 备份由新版恢复。

## 分工与验证

1. 数据库负责人：实体、V4 迁移、仓储日期查询、备份校验与持久化测试。
2. 业务负责人：两个 Tab 的独立状态、编辑器、日历命令及业务测试。
3. 前端负责人：WPF Tab、两套主题、编辑弹窗和日历展示。
4. 集成负责人：Excel、文档、代码复核、构建及回归验证。

验收覆盖旧库/旧备份升级、类型及日期保存、附件保留、两 Tab 隔离、接受条件按接受日进入日历、两类导出、备份往返，以及亮暗主题和 WPF 界面冒烟测试。
