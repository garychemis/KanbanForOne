# 设计条件多图幅归档改造计划（单行分隔存储方案）

## 1. 方案结论

不新增图幅明细表，继续保持“一条设计条件对应 `DesignConditions` 表中的一行”。

同一条件包含多种图幅时，分别在现有图幅和数量字段中按相同顺序使用半角竖线 `|` 分隔：

```text
DrawingSize  = A1|A4
DrawingCounts = 1|5
DrawingCount  = 6
```

应用读取后按数组位置配对：

| 序号 | 条件图幅 | 条件数量 |
| ---: | --- | ---: |
| 1 | A1 | 1 |
| 2 | A4 | 5 |

该数据库行仍代表 `1 条`逻辑设计条件，条件总张数由数量项求和得到 `6 张`，附件关系和附件目录继续使用原条件 `Id`，不发生变化。

## 2. 采用此方案后的边界

### 2.1 优点

- 不增加数据表和外键关系；
- 每条条件仍只有一个稳定 `Id`，现有编辑、删除、附件和日期刷新逻辑基本保留；
- 不会因为多种图幅造成条件记录数、附件数重复；
- 数据库查看时仍能在一行内看到全部图幅和数量；
- 比“主表重复多行后按业务字段合并”更可靠，不会误合并两条字段相同但实际独立的条件。

### 2.2 代价

- 新增一个 `DrawingCounts TEXT` 列保存逐规格数量；现有 `DrawingCount INTEGER` 继续保存总张数；
- 保存时必须同时维护分隔明细和整数总数，不能让二者失配；
- 图幅和数量两个字符串必须保持相同项数和相同顺序；
- 自定义图幅不能包含分隔符 `|`；
- 将来若要直接在 SQL 中按图幅筛选、排序或统计，分隔字符串不如明细表方便。

## 3. 存储协议

### 3.1 正常格式

```text
DrawingSize  = A1|A4|A3加长
DrawingCounts = 1|5|2
DrawingCount  = 8
```

配对结果为 `A1 × 1`、`A4 × 5`、`A3加长 × 2`，总张数为 `8`。

### 3.2 写入规范

- 仅使用半角 `|` 作为分隔符；
- 图幅和数量字段不在分隔符两侧保存多余空格；
- 图幅按 UI 当前显示顺序写入，数量严格使用相同顺序；
- 图幅文本保存前去除首尾空白；
- 数量使用大于 `0` 的十进制整数标准文本，不保存小数、单位、正号或千位分隔符；
- 图幅中禁止出现 `|`，发现时阻止保存并给出明确提示；
- 同一条件内图幅按不区分大小写比较，不允许重复；发现重复图幅时阻止保存并明确提示；
- 至少保存一组有效的“图幅 + 数量”。

### 3.3 旧数据兼容

旧数据本身就是单项形式：

```text
DrawingSize  = A1
DrawingCounts = 3
DrawingCount  = 3
```

新解析器将没有 `|` 的值自然识别为一行 `A1 × 3`，迁移不改变其业务内容。

### 3.4 异常数据处理

统一解析器遇到以下情况时，不能静默错配：

- 图幅项数与数量项数不同；
- 存在空图幅、空数量或连续分隔符；
- 数量不是整数、超出 `Int32` 范围或小于等于 0；
- 图幅重复；
- 所有数量求和超过 `Int32.MaxValue`。

正常 UI 保存会提前阻止这些数据产生。若数据库被外部工具改坏，读取时保留主记录并显示“图幅数据格式异常”，主页面使用已保存的整数总张数作为兼容回退，同时禁止直接覆盖保存，用户进入详情后修正数据。错误信息应包含条件名称和具体原因，方便定位。

## 4. 数据库调整计划

### 4.1 schema v3

将设计条件独立数据库由版本 `2` 升级为版本 `3`，不新增表，也不重建主表：

- `DrawingSize` 继续为 `TEXT NOT NULL DEFAULT ''`；
- 新增 `DrawingCounts TEXT NOT NULL DEFAULT ''` 保存逐规格数量；
- `DrawingCount INTEGER NOT NULL DEFAULT 0` 继续保存总张数并保留非负约束；
- 其他字段、主键和索引保持不变；
- `DesignConditionAttachments.DesignConditionId` 外键仍引用原主记录 `Id`。

不直接向 SQLite 的 `INTEGER` 列写入 `1|5`。新增文本列的迁移只需 `ALTER TABLE ADD COLUMN`，同时保留现有总数查询、日历 `SUM`、备份和旧代码兼容能力。

### 4.2 迁移步骤

1. 在一个 SQLite 事务中为 `DesignConditions` 增加 `DrawingCounts` 文本列。
2. 使用 `CAST(DrawingCount AS TEXT)` 把每条旧记录的总数初始化为单项数量明细。
3. 保留全部原字段、原 `Id`、索引和附件外键。
4. 校验主记录数、附件外键、图幅值和数量值；旧总张数在迁移前后必须一致。
5. 设置 `PRAGMA user_version = 3` 后提交；任何失败整体回滚。
6. 更新备份清单和数据库结构验证。v1/v2 备份仍可恢复，恢复完成后由初始化流程自动升级到 v3。

## 5. 统一解析与领域模型

### 5.1 图幅行模型

新增仅用于应用层和 UI 的 `DesignConditionDrawingRow`：

```text
DrawingSize
DrawingCountText
DrawingCount（校验成功后的整数）
```

它不是数据库表实体，保存时会重新序列化到现有两个字段。

### 5.2 编解码器

增加单一 `DesignConditionDrawingCodec`，所有模块必须通过它处理分隔字符串：

- `Parse(sizeText, countText)`：返回有序图幅行或结构化错误；
- `Serialize(rows)`：完成标准化、校验并生成两个存储字符串；
- `GetTotalCount(...)`：安全求和并检查整数溢出；
- `GetSummary(...)`：生成 `A1 × 1 · A4 × 5`；
- `ContainsSize(...)`：用于搜索图幅。

编解码器在序列化前按图幅名称不区分大小写检查重复项；发现重复时返回错误，不自动合并。所有数量之和必须在 `Int32` 范围内。

禁止主页面、日历、导出服务分别使用 `Split('|')` 自行解释，以免边界处理和统计口径不一致。

### 5.3 `DesignConditionEntry`

- 数据库存储值由仓储读取后通过编解码器解析；
- 对外提供只读的图幅行集合；
- `DrawingCount` 继续作为“总张数”整数属性，尽量保持现有主页面、日历和汇总绑定不变；
- 新增完整图幅摘要和数据格式错误状态；
- 附件集合、条件 `Id` 和其他公共字段不变。

## 6. 详情页面 UI 规划

需求中的 `DataGridView` 在当前 WPF 项目里对应 WPF `DataGrid`。

### 6.1 页面布局

删除原有并排的单个“图幅”下拉框和“图纸数量”文本框，改为一个“条件图纸”卡片：

```text
条件图纸                         共 2 种规格 · 6 张    [＋ 添加规格]
┌────────────────────┬──────────────────┬────────┐
│ 条件图幅           │ 条件数量         │ 操作   │
├────────────────────┼──────────────────┼────────┤
│ A1                 │ 1                │ 删除   │
│ A4                 │ 5                │ 删除   │
└────────────────────┴──────────────────┴────────┘
```

- 表格两列为“条件图幅”“条件数量”，第三列只放行内删除按钮；
- 新建条件默认显示一条图幅为空、数量为 `1` 的明细行，方便直接输入；
- 表格显示 3～5 行的舒适高度，更多行时在表格内部滚动；
- 保持附件区域和底部保存/取消按钮可见，不让表格无限撑高弹窗；
- 禁止用户点击列头排序，确保 UI 顺序与两个分隔字符串的配对顺序一致；
- 表格不自动生成额外空白行，新增统一通过“添加规格”按钮完成。

### 6.2 新增图幅

点击“＋ 添加规格”后：

1. 在末尾增加一条空行；
2. 自动选中新行并将焦点放到“条件图幅”单元格；
3. 图幅单元格使用可编辑 `ComboBox`，候选值复用 A0～A4 和历史自定义图幅；
4. 选择或输入图幅后，按 `Tab` 进入数量单元格；
5. 数量输入完成后按 `Enter` 提交单元格编辑；需要下一行时再次点击添加。

若当前最后一行已经完全空白，再点击添加时直接聚焦该空白行，不继续制造多个空行。

### 6.3 编辑图幅

- 单击选中行，双击单元格或按 `F2` 进入编辑；
- 图幅支持从候选项选择或输入自定义文本；
- 自定义图幅不能包含半角 `|`；保存校验检测到该字符时显示带行号的提示并阻止落库；
- 数量单元格只接受整数文本，粘贴非法字符时显示行级错误；
- 每次单元格提交后重新计算“规格数”和“总张数”；
- 提交图幅或保存时若发现与现有行重复，则保留用户输入并显示错误，阻止保存，直到用户删除或修改重复行；
- 修改尚未保存到数据库，点击“取消”应放弃本次所有图幅、公共字段和附件待处理变更；
- 打开旧单图幅条件时自动显示为一行，用户可以继续添加其他规格。

### 6.4 删除图幅

- 每行末尾提供“删除”按钮；
- 删除只影响弹窗中的待保存状态，不立即写数据库，因此不需要二次确认；
- 删除后立即更新规格数和总张数；
- 删除最后一行后自动补一条空行，使页面始终有可编辑入口；
- 点击“取消”后原数据库数据不变；点击“保存”时才整体写回两个分隔字段。

### 6.5 ViewModel 命令和状态

编辑 ViewModel 增加：

- `ObservableCollection<DesignConditionDrawingRow> DrawingRows`；
- `AddDrawingRowCommand`；
- `RemoveDrawingRowCommand`；
- `DrawingSpecificationCount`；
- `TotalDrawingCount`；
- `HasDrawingErrors` 和行级错误信息。

每行属性变化都触发总数和整体验证更新；移除行时解除事件订阅，避免弹窗多次打开后的引用残留。

### 6.6 保存校验顺序

保存时按以下顺序校验：

1. 结束当前 DataGrid 单元格/行编辑，确保最后输入值进入 ViewModel；
2. 去掉完全空白的尾部占位行；
3. 检查至少存在一条有效规格；
4. 检查每行图幅非空且不包含 `|`；
5. 检查数量为大于 `0` 的整数；
6. 按图幅不区分大小写检查重复项，发现重复时阻止保存；
7. 检查所有数量求和不超过 `Int32.MaxValue`；
8. 使用统一编解码器生成 `DrawingSize`、`DrawingCounts` 分隔字符串和 `DrawingCount` 整数总数；
9. 与公共字段、附件变更一起进入现有 SQLite 聚合保存事务。

错误提示应指明行号，例如：`第 2 行：条件数量必须是大于 0 的整数。`

## 7. 仓储、统计和查询调整

### 7.1 仓储

- SQL 同时写入 `DrawingSize`、`DrawingCounts` 和整数总数 `DrawingCount`；
- Reader 读取两段分隔字符串并通过编解码器解析，总张数异常时使用整数列兼容回退；
- `SaveAggregateAsync` 的事务范围保持不变，只更新同一条主记录；
- 图幅候选项从解析后的所有行收集，不再只收集一个 `DrawingSize` 字符串。

### 7.2 主页面

- “条件记录”继续等于逻辑数据库行数；
- 顶部“图纸总量”对各记录解析后的总张数求和；
- 主列表“图纸”列以总张数为主，例如 `6 张`，下方显示图幅摘要 `A1 × 1 · A4 × 5`；
- 图幅摘要过长时截断，并通过 ToolTip 查看完整内容；
- 关键词搜索增加对每个解析后图幅的匹配，不直接搜索整段分隔字符串。

### 7.3 图纸量汇总

- 记录数仍按一条数据库行计数；
- 图纸数量使用解析后的总张数；
- 附件数不受图幅数量影响；
- 无效分隔数据不导致页面崩溃，并向模块错误区报告具体记录。

### 7.4 日历

现有 `DrawingCount INTEGER` 继续保存总张数，因此日历仍可使用 SQL `SUM(DrawingCount)` 高效汇总：

- `RecordCount`：该日期逻辑条件行数；
- `DrawingCount`：该日期所有数量项之和；
- 选中日期列表仍显示一条逻辑条件一项，并显示总张数和图幅摘要。

日历常用查询范围只有当前 42 天网格，应用层解析成本可控。

## 8. Excel 导出调整

- “设计条件汇总”保持一条逻辑条件只计一次，图纸数量使用解析后的总张数；
- “设计条件明细”采用“一种图幅一行”：一条条件含 A1、A4 时输出两行，公共条件字段随行重复；
- “图幅”列只输出当前行规格，例如 `A1`；“图纸数量”列只输出该规格数量，例如 `1`；
- 新增“条件总张数”列，两行均输出该逻辑条件总数 `6`，方便阅读整条条件规模；
- 附件数和附件文件名随公共字段重复，Excel 汇总统计必须以“设计条件汇总”工作表为准，不能对展开后的附件数直接求和；
- 汇总工作表仍在展开前按逻辑条件计算记录数、附件数和总张数，不能因一种图幅一行而重复累计。

## 9. 备份与恢复调整

- 备份格式本身不变，仍打包一个数据库和附件目录；
- 清单中的数据库 schema 版本升级为 `3`；
- 备份验证确认 v3 数据库包含 `DesignConditions.DrawingCounts` 文本列；
- v1/v2 备份继续允许导入，安装后执行数据库迁移；
- 恢复后的模块重新加载时必须验证旧总张数和附件数量未变。

## 10. 测试计划

### 10.1 编解码测试

- `A1|A4` 与 `1|5` 正确解析并求和为 6；
- 单项旧格式 `A1` 与 `3` 正确解析；
- 序列化后顺序保持不变；
- 前后空白被标准化；
- 项数不一致、空项、负数、溢出和图幅包含 `|` 均返回明确错误；
- 数量 `0`、负数、小数和非数字文本均被拒绝；
- 重复图幅按不区分大小写检查并返回明确错误；
- 解析后再序列化可得到稳定的标准字符串。

### 10.2 数据库和仓储测试

- v2 的整数数量列迁移为 v3 文本列，记录数、总张数和附件不变；
- 多图幅记录可保存、读取、编辑和删除某个 UI 行；
- 保存公共字段、分隔字段和附件变更时保持单一事务；
- 保存失败后数据库和附件文件均正确回滚；
- 旧版本备份恢复后自动迁移成功。

### 10.3 统计和导出测试

- 一条条件 `A1=1、A4=5`：条件数为 1，总张数为 6；
- 多条条件在筛选、分级汇总和日历中的条件数与总张数正确；
- 附件数不因规格数增加而重复；
- Excel 明细按一种图幅一行展开，并输出该规格数量和条件总张数；汇总与主页面一致且不重复累计。

### 10.4 UI 测试

- 新建默认一行且数量为 `1`，可连续添加多行；
- 单元格编辑、Tab/Enter 提交和实时总数正常；
- 删除中间行后剩余图幅与数量仍正确配对；
- 删除最后一行会补空白行；
- 重复图幅阻止保存；分隔符、空图幅、数量 `0`、负数和其他非法数量阻止保存；
- 打开旧条件显示一行，保存后仍保持相同值；
- 多行表格不会遮挡附件区和底部按钮；
- 取消编辑不会落库。

## 11. 实施顺序

1. **确认口径**：新增规格默认数量为 1，数量只允许大于 0 的整数，重复图幅阻止保存，自定义图幅禁止使用分隔符 `|`，Excel 明细按一种图幅一行，主列表显示总张数和图幅摘要。
2. **编解码器与测试**：先锁定分隔协议和异常数据行为。
3. **schema v3 迁移**：把数量列改成文本并验证旧数据、附件和备份兼容。
4. **领域模型与仓储**：统一解析、序列化、总数和摘要属性。
5. **详情页 DataGrid**：实现新增、编辑、删除、焦点、校验和实时合计。
6. **主页面与日历**：替换所有单图幅假设和 SQL 数值求和。
7. **汇总、导出和备份**：统一统计口径并升级结构验证。
8. **全量回归**：运行单元测试、备份恢复测试、UI smoke、完整构建和人工冒烟。

## 12. 已确定口径

1. 条件数量只允许大于 `0` 的整数，新增规格默认数量为 `1`。
2. 同一条件出现重复图幅时，按不区分大小写检查并阻止保存，不自动合并。
3. 自定义图幅禁止包含半角 `|`，这是双字段分隔协议的必要限制。
4. Excel“设计条件明细”采用一种图幅一行，并额外输出条件总张数。
5. 主列表采用“总张数为主、图幅摘要为辅”，例如 `6 张 / A1 × 1 · A4 × 5`。
